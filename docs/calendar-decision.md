# 日历方案结论与后续范围（P5.4）

Phase 5 的问题是：`@tt` 能否在用户确认后形成一份计划，修改 / 取消不会重复生成，已经开始后还能保护原截止？[单文件离线原型](examples/calendar-prototype.html) 在虚构事件和内存状态中给出了可复核的肯定结果。**决定进入后续的 Google 只读接入验证，先做读取和预览，再连接调度；不直接把原型接进产品。**

本阶段属于 ideation，当前 App 仍没有 Google / Apple 日历授权或同步。路线依据见 [官方接入调研](calendar-provider-research.md)，产品契约见 [实例映射](calendar-mapping.md)。本次用户要求每个 MVP 提交到 main，因此原型作为可丢弃的证据保存在 `docs/examples`，没有产品入口、没有导入生产代码，也不进入 App 的打包文件。

## 如何查看样例

双击 `docs/examples/calendar-prototype.html` 即可离线打开，无须安装或启动服务。点击一个场景页签会清空本次内存，按有颜色的步骤按钮推进；也可以使用“自由尝试”。“查看完整模拟记录”显示身份键、固定计划 ID、生效时刻和领取快照。

页面用普通 JavaScript 的纯状态模型和一个独立显示层。事件字段采用 Google Events 的标题、描述、起止和重复身份形状，但**不是从 API 获取的响应**。这里只手工提供明确事件包，不能把它说成已经实现 Google 全量分页、`syncToken` 或真实增量同步。模拟到点仅增加计数，模拟重开仅保留内存快照；刷新页面会清空。没有账号、持久化、网络请求、浏览器课堂、签到或答案回执。

## 可行性证据

在本机 Chrome 打开实际 HTML，自动点击六组逐步演练的 35 个按钮。31 个页面产生的任务投影通过当前 Phase 4 的 `validateSchedule`；另外检查自由尝试的首次确认门禁和断网恢复后必须重新启用。脚本错误为零，除本地文件外的请求为零；900×640 和 390×844 页面核对通过。

| 场景 | 实际观察 |
| --- | --- |
| 确认 → 重读 → 改时 → ID-only 取消 | 首次确认前没有任务；同一计划 ID，重读不改生效时刻；改时更新日期，取消只停用 |
| 领取 → 跨日改时 → 模拟重开 → 再次到点 | 模拟开始保持一次；日期投影和原截止不变；改时、重开、取消不能重新开始 |
| 本机暂停 → 读取失败 → 恢复 → 明确启用 | 恢复读取保持暂停；只有人工重新启用后才能模拟到点 |
| 两个重复实例 → 改第一节 → 取消第二节 | 两份独立计划，没有第三份；原定实例身份保留，另一节不被误删 |
| 同名课程与未指定结束 | 不能直接确认；明确选择课程后可生成；缺少结束时停用，补齐后再明确启用 |
| 回拨第二个 01:30（-06:00） | UTC 07:30 单次计划，原截止 UTC 08:20；没有落到较早一次 |

这些结果验证模型和交互，不验证真实授权、账号同步时序、系统重启、磁盘原子写入或实际课堂。首次在同一页面调整到窄屏后，全页截图出现重复拼接；新建独立 390×844 页面、等待绘制后截图正常，DOM 仅一个 main、无横向页面溢出。没有把截图拼接异常当作产品缺陷或隐藏为从未出现。

## Google 和 Apple 各自状态

| 路线 | 当前结论 | 继续开发的条件 |
| --- | --- | --- |
| Google | 官方接口调研完成；离线普通文本 / 实例模型可行；实际 OAuth / API 未连接 | 独立合成日历与账号授权、完整分页、取消、撤销、身份核实和错误恢复先通过 |
| Apple EventKit | 官方权限和身份限制已记录；当前原型没有 EventKit 输入适配或原生桥接 | 单独验证 macOS 13 / 14+ 的 full access、拒绝 / 撤销、重复例外和身份重建 |
| iCloud / CalDAV | 候选研究；本 App 的第三方授权资格和协议行为未核实 | 明确资格、权限粒度及发现 / 同步能力后再决定；Windows Apple 读取继续待研究 |

Google 的首个真实 MVP 建议只支持一条连接和少量选定日历。读取为普通文本；HTML 描述在原型中直接拒绝，不能执行或加载外部内容。真实读取需要安全的文本转换。初期仅支持明确瞬间、整分钟、1–720 分钟的单次 / 来源展开实例；全天、浮动 / 歧义时间、缺少结束和未知身份均留在补齐界面。复制事件与跨来源自动合并暂不承诺。

## 后续实现检查点（未开始）

- [ ] **C1 — 隔离授权与读取。** 使用独立测试项目和合成日历验证 Desktop OAuth / PKCE、账号身份、最少权限、选定日历、完整分页及令牌失效；取消 / 拒绝 / 撤销分别显示。不得将未完成页面或权限缺失当删除。验收只读调用及撤销后无继续读取，不启动课堂。
- [ ] **C2 — 识别预览与来源批次。** 实现安全文本转换、精确课程匹配、首次 / 换课确认、来源时区展示、同版本去重、乱序请求丢弃和完整窗口缺失核对。覆盖 P5.1 的 16 个语义例子及 P5.3 的边界；源失败与本机暂停分开。验收不默认猜时间、不自行启用。
- [ ] **C3 — 持久绑定与原子领取。** 为现有 Store / Scheduler 增加日历实例身份、稳定计划 ID、独立执行事实及同一次原子领取；迁移旧数据。注入保存失败、领取后中断、跨日改时、取消并发、410 / 重连和删除课程，证明没有重复课堂副作用。内存原型不能替代此验收。
- [ ] **C4 — 受控调度连接。** 复用 Phase 4 的 UTC 单次投影、冲突、十分钟宽限、原截止和环境门禁；实际 App 重开 / 来源恢复 / 托盘 / 焦点 / 退出通过 macOS 与 Windows 隔离验收。真实课堂与回执由使用者另验，计划建立和模拟计数不能显示成签到成功。
- [ ] **C5 — 小范围使用验收。** 面向不了解电脑知识的使用者走查连接、确认、补齐、暂停、重新授权与断开；验证日志最少化、安全令牌存储和彻底删除提示。明确授权范围、App 常驻及睡眠限制后才考虑发布。
- [ ] **A1 — Apple 专项可行性。** C1–C3 的接口稳定后，单独验证 EventKit 本机权限 / 签名 / 桥接 / 身份变化；选择对应的来源适配方式。未经验证不把 Apple 或 Windows iCloud 写成已有功能。

进入这些检查点前仍需安排真实授权与系统平台验收；本轮没有为后续阶段创建账号、申请权限、修改私人事件或发布下载包。

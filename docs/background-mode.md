# 后台模式实现与验证

## P3.4 中断恢复与退出（2026-10-01）

后台专用 Chrome 意外退出后显示“正在重连”，最多三次尝试并重新核实页面；失败后保留原截止时间并提供人工恢复入口。有窗口课堂主动关闭仍保持暂停，不自动抢焦点。恢复与睡眠唤醒沿用原会话、绝对结束时间及已尝试 / 已确认记录；未确认的旧尝试不自动重复提交。

App 崩溃重开后显示“上次监控已中断”和 **恢复上次课堂**，启动本身不继续监控。若专用 Chrome 仍在运行，先清除旧页面动作门禁和定位覆盖；用户恢复后再核实原课程，已过期则保持结束并关闭残留专用进程。选择重新开始另一节课会保存旧中断摘要。关闭主界面保持托盘运行；手动结束停止动作，退出 App 等待正在进行的准备 / 模式操作并清理浏览器、定时器、通知和定位。

### P3.1 首次 Windows 超时复核

旧失败日志定位在 `integration.mjs` 的最后窗口关闭后 `browser.show()`，错误为“专用 Chrome 连接超时”。通过 `npx vitest run tests/browser-lifecycle.test.ts` 在真实浏览器接口的事件边界注入“CDP 已断开、PID 尚未退出”，修复前检测到新启动已发出，修复后通过。共同关闭路径现在等待已核实的浏览器 PID 实际退出，再允许同一资料重开；不再只等 CDP 断开。实际生命周期检查改为立即重开，并增加四轮连续关窗 / 重开；取消启动也有回归检查。

这是对可复现的同类时序缺陷的修复。首次 Windows CI 没有记录 PID / 资料锁时序，无法唯一证明当时的具体原因；历史失败仍保留，不用重跑或后续绿色掩盖它。验证结果见下方及 [验证记录](../VERIFICATION.md)。

本机验证：73 单测（含退出等待的失败 → 修正通过、取消启动清理、最多三次重连、重启保留未确认记录、过期不启动、受控唤醒和停止后的二次清理）、双 renderer、25 原有集成、九组后台运行、立即重开及四轮连续生命周期检查、生产构建与 Mac 实际打包五组恢复通过。实际测试强制结束 App 和专用 Chrome，确认恢复沿用原会话 / 截止 / 回执、后台重新连接、过期清理及所有记录的专用进程退出。首次恢复测试误用旧构建，旧动作门禁断言失败；重新打包后通过，未把旧包结果作为最新源码的证据。

Mac 仍用隔离合成加密；Windows 本功能提交 CI 待完成。物理睡眠、真实课堂 / 学校验证、Keychain 和真人通知继续独立待验证。Windows 的同类竞态与安装版恢复将在本次 CI 中验证，历史首次超时的唯一原因仍不能从旧日志证明。

## P3.3 人工处理与返回后台（2026-10-01）

后台遇到登录过期、学校验证、人工题或无法识别页面时，App / 托盘显示对应状态并发送提醒。自动检查不打开窗口、不改变前台焦点；用户点击课堂通知、登录或查看入口时，打开正在监控的正确课程。学校验证仍由用户在可见窗口完成，网站当前页面是判断依据。

可见课堂期间，App 与托盘提供 **返回后台**。先等待当前检查结束，再核实页面属于本节课程、页面可识别且没有弹窗，并检查当前开放题目的网站答案回执。未确认答案（包括已有选择）、未完成登录、断网、错误页面或专用浏览器中的其他标签页都会阻止关闭，给出处理提示并保留页面。托盘操作失败也发送具体原因提醒。确认后串行保存加密登录、关闭旧进程、启动 Headless、打开本节课程，重新检查网站。

本次切换不更改下一节偏好，也不重新创建会话、延长课程或清空处理记录。停止或到期的信号会阻止后续重新设定动作门禁；结束后不能返回后台继续本节课。已结束题目的临时输入不属于可恢复草稿，网站未保存的 DOM / 表单状态仍不保证跨 Chrome 重启保留。

本机通过：66 单测、双 renderer（900×640 返回与完整结束按钮可见）、九组后台运行、25 项原有集成，以及最终 macOS 实际打包 App。九组运行覆盖人工草稿被拦截后原值仍在、网站确认后返回后台且系统可见窗口为零、原会话 / 截止 / 两题记录保留、未重复提交；登录过期与未知页面提醒不抢焦点、学校验证等待、额外标签页保护、结束后返回被拦截。首次运行发现模拟学校验证页被误判为未知页面，已补充识别后通过复测，未将失败隐藏为一次成功。

实际打包测试向真实课堂 `Notification` 实例注入 `click`，确认处理器打开正确课堂；调用真实托盘 `MenuItem` 的返回入口验证失败提醒，再用 App 按钮返回后台。此为自动化方法 / 事件验证，不代表真人看到或点击系统提醒。Mac 合成加密仅用于隔离测试进程，生产代码保持 `safeStorage`。同一功能提交 [`6ee7269`](https://github.com/tzuo5/attendance-handler/commit/6ee7269) 的 [Source checks](https://github.com/tzuo5/attendance-handler/actions/runs/36833334278) 与 [Windows CI](https://github.com/tzuo5/attendance-handler/actions/runs/36833334316) 首次尝试全部通过，包含相同九组运行、实际安装版人工往返、首次向导、真实 DPAPI 和包审核；真实课堂、学校验证、实体设备、钥匙串与真人提醒保持待验收。

## P3.2 设置与后台运行（2026-10-01）

在“连接与提醒”选择 **显示课堂窗口** 或 **后台模式（无 Chrome 窗口）**。默认显示窗口，旧资料自动采用此默认值；偏好保存于本机并从下一次上课生效，本节不会因设置变化突然关闭课堂。选中方式用按钮状态显示。

开始上课按偏好复用专用资料；需要切换时，等待现有操作完成、保存加密登录、关浏览器并等待旧 PID 退出，再启动所选模式。保存加密失败会保留可用窗口并报告问题。App 与托盘显示实际模式，关闭主界面继续监控；点击查看、登录或课堂通知会串行打开可操作窗口，保留会话、处理记录和原截止时间。“处理后返回后台”入口由下方 P3.3 提供。

本机验证：64 单测、两套 renderer、六组后台运行、六组模式往返、25 项原有集成、生命周期、生产构建和实际 macOS 打包 App / 首次向导通过。新增 `npm run test:background-runtime` 验证无窗口签到与确认作答、前台焦点、偏好下次生效、加密失败、显式查看及受控时钟到期门禁。实际 App 测试关闭主界面后继续确认单次答案，收到人工题状态；托盘通过真实方法调用采集其课程、状态、模式与操作入口，未把方法调用采集视为真人点击托盘。

测试报告仍仅保存在 `.test-artifacts/phase3/` 与忽略提交的 UI 报告中。Mac 使用合成加密的验证边界延续 Phase 2；功能提交 `fe68166` 的 [Windows CI](https://github.com/tzuo5/attendance-handler/actions/runs/36830875240) 首次尝试全部通过，包含相同后台运行、实际安装版后台 UI、真实 DPAPI 与包审核。界面修正 `52813d5` 使设置后回到课程页时显示当前模式和完整结束按钮，本机 renderer 与生产构建通过；该修正的 [Windows CI](https://github.com/tzuo5/attendance-handler/actions/runs/36831375710) 已全部通过。真实课堂、钥匙串、通知和实体设备边界保持待验收。进程退出等待仅验证了正常模式切换，没有把 P3.1 首次 Windows 关窗恢复超时标为已修复；异常重连和 App 重启仍属 P3.4。

## P3.1 可行性结论（2026-10-01）

采用 **一个专用资料目录、串行重启 Chrome** 的方案。先保存加密登录会话并关闭旧进程，确认旧进程退出，再用相同资料启动有窗口或统一 Headless Chrome。监控会话不重新创建，继续使用原有题目处理记录和原截止时间。

| 方案 | 结果与取舍 |
| --- | --- |
| 最小化或移出屏幕 | 仍有 Chrome 窗口，不满足后台模式要求；保留原有最小化功能 |
| 有窗口和 Headless 同时打开相同资料 | 存在资料锁与不确定目标问题，不采用 |
| 使用两个资料复制凭据 | 页面与登录可能分叉，扩大凭据处理范围，不采用 |
| 同一资料串行重启 | 模拟课堂完整往返通过；切换有短暂重连，需复核页面 |

Chrome 的统一 Headless 用 `--headless` 启动，平台窗口会创建但不显示，见 [Chrome 官方说明](https://developer.chrome.com/docs/automation-and-testing/headless)。因此测试核实的是**没有可见窗口**，不把所有内部平台窗口数量为零作为要求。macOS 通过 Core Graphics 的屏幕窗口列表查询专用浏览器进程；Windows 通过 `EnumWindows` / `IsWindowVisible` 查询。

## 隔离验证

先 `npm run build` 编译原生辅助程序，再运行 `npm run test:background-feasibility`。测试只连接本机模拟服务，使用临时专用资料、零值坐标及合成 AES-GCM 加密器；不会读取个人 Chrome 资料。报告保存在忽略提交的 `.test-artifacts/phase3/feasibility-report.json`。

2026-10-01 在 Apple Silicon macOS、Chrome **154.0.8037.58** 上通过六组检查：

1. 有窗口完成模拟登录，保存加密会话和专用持久 Cookie。
2. 关闭旧进程后转 Headless；登录、Cookie、会话标识和原截止时间保留；系统可见窗口为零，前台焦点不变。
3. Headless 完成签到和一次 A 作答，按页面回执分别确认。
4. 转回有窗口后保持已确认答案，没有重复提交。
5. 新题转人工、收到提醒、有窗口提交合成答案，再回 Headless；已提交答案与原截止时间保留。
6. 四个串行浏览器进程均退出；资料没有同时被两个实例占用，没有残留专用 Chrome。

同一功能提交 `334b2fb` 的 [Windows CI](https://github.com/tzuo5/attendance-handler/actions/runs/36827376760) 第二次尝试全部通过：相同六组原型检查、60 单测、25 项原有集成、专用浏览器生命周期、双套 renderer、实际安装版 UI / 首次向导、真实 DPAPI 恢复及包审核。平台为托管 Windows Server 2022 x64。首次尝试在原有集成的“最后窗口关闭后重新打开”步骤发生连接超时，未进入新增原型测试；重跑通过不证明该偶发时序问题已修复，P3.4 继续复核进程退出与资料锁释放。

本检查点只交付底层启动能力和可执行原型。App 设置、切换操作的并发门禁和用户入口属于 P3.2/P3.3；自动重连和 App 重启恢复属于 P3.4。真实学校验证、真实课堂、macOS 系统钥匙串与实体设备仍待独立验收。

页面通过网站或现有加密会话恢复；**未提交的表单草稿、网页中的临时 DOM 状态不保证保留**。切回后台须在人工处理完成后进行，并再次核实网站答案回执，不能把重新加载视作提交成功。

## 生命周期规则

| 动作 | 目标行为 | 实现检查点 |
| --- | --- | --- |
| 关闭 App 主界面 | 托盘继续运行当前课堂，保持原截止时间 | P3.2 |
| 切换模式 | 串行保存、关浏览器、重启、复核页面；保留处理记录和原截止时间 | P3.2/P3.3 |
| 关闭有窗口课堂 | 明确暂停并提供恢复入口，不偷偷抢回焦点 | P3.3/P3.4 |
| 专用后台浏览器崩溃 | 显示重连，限定重试；无法恢复时提供人工入口 | P3.4 |
| 重启 App | 展示中断记录；恢复时保留原截止时间和去重记录，并核实当前页面 | P3.4 |
| 结束课堂 | 清理检查、提醒与定位，截止后不允许继续自动动作 | P3.2/P3.4 |
| 退出 App | 结束监控并清理专用浏览器，避免后台残留 | P3.4 |

上述规则为后续检查点的验收约定；P3.1 原型没有提前把 App 设置和恢复入口标为完成。

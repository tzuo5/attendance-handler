# 后台模式实现与验证

## P3.2 设置与后台运行（2026-10-01）

在“连接与提醒”选择 **显示课堂窗口** 或 **后台模式（无 Chrome 窗口）**。默认显示窗口，旧资料自动采用此默认值；偏好保存于本机并从下一次上课生效，本节不会因设置变化突然关闭课堂。选中方式用按钮状态显示。

开始上课按偏好复用专用资料；需要切换时，等待现有操作完成、保存加密登录、关浏览器并等待旧 PID 退出，再启动所选模式。保存加密失败会保留可用窗口并报告问题。App 与托盘显示实际模式，关闭主界面继续监控；点击查看、登录或课堂通知会串行打开可操作窗口，保留会话、处理记录和原截止时间。完整“处理后返回后台”入口在 P3.3 实现。

本机验证：64 单测、两套 renderer、六组后台运行、六组模式往返、25 项原有集成、生命周期、生产构建和实际 macOS 打包 App / 首次向导通过。新增 `npm run test:background-runtime` 验证无窗口签到与确认作答、前台焦点、偏好下次生效、加密失败、显式查看及受控时钟到期门禁。实际 App 测试关闭主界面后继续确认单次答案，收到人工题状态；托盘通过真实方法调用采集其课程、状态、模式与操作入口，未把方法调用采集视为真人点击托盘。

测试报告仍仅保存在 `.test-artifacts/phase3/` 与忽略提交的 UI 报告中。Mac 使用合成加密的验证边界延续 Phase 2；Windows 本次工作流已加入相同后台运行与安装版 UI，结果待推送后确认。真实课堂、钥匙串、通知和实体设备边界保持待验收。进程退出等待仅验证了正常模式切换，没有把 P3.1 首次 Windows 关窗恢复超时标为已修复；异常重连和 App 重启仍属 P3.4。

## P3.1 可行性结论（2026-10-01）

采用 **一个专用资料目录、串行重启 Chrome** 的方案。先保存加密登录会话并关闭旧进程，确认旧进程退出，再用相同资料启动有窗口或统一 Headless Chrome。监控会话不重新创建，继续使用原有题目处理记录和原截止时间。

| 方案 | 结果与取舍 |
| --- | --- |
| 最小化或移出屏幕 | 仍有 Chrome 窗口，不满足后台模式要求；保留原有最小化功能 |
| 有窗口和 Headless 同时打开相同资料 | 存在资料锁与不确定目标问题，不采用 |
| 使用两个资料复制凭据 | 页面与登录可能分叉，扩大凭据处理范围，不采用 |
| 同一资料串行重启 | 模拟课堂完整往返通过；切换有短暂重连，需复核页面 |

Chrome 的统一 Headless 用 `--headless` 启动，平台窗口会创建但不显示，见 [Chrome 官方说明](https://developer.chrome.com/docs/automation-and-testing/headless)。因此测试核实的是**没有可见窗口**，不把所有内部平台窗口数量为零作为要求。macOS 通过 Core Graphics 的屏幕窗口列表查询专用浏览器进程；Windows 通过 `EnumWindows` / `IsWindowVisible` 查询。

## 隔离验证

先 `npm run build` 编译原生辅助程序，再运行 `npm run test:background-feasibility`。测试只连接本机模拟服务，使用临时专用资料、零值坐标及合成 AES-GCM 加密器；不会读取个人 Chrome 资料。报告保存在忽略提交的 `.test-artifacts/phase3/feasibility-report.json`。

2026-10-01 在 Apple Silicon macOS、Chrome **154.0.8037.58** 上通过六组检查：

1. 有窗口完成模拟登录，保存加密会话和专用持久 Cookie。
2. 关闭旧进程后转 Headless；登录、Cookie、会话标识和原截止时间保留；系统可见窗口为零，前台焦点不变。
3. Headless 完成签到和一次 A 作答，按页面回执分别确认。
4. 转回有窗口后保持已确认答案，没有重复提交。
5. 新题转人工、收到提醒、有窗口提交合成答案，再回 Headless；已提交答案与原截止时间保留。
6. 四个串行浏览器进程均退出；资料没有同时被两个实例占用，没有残留专用 Chrome。

同一功能提交 `334b2fb` 的 [Windows CI](https://github.com/tzuo5/attendance-handler/actions/runs/36827376760) 第二次尝试全部通过：相同六组原型检查、60 单测、25 项原有集成、专用浏览器生命周期、双套 renderer、实际安装版 UI / 首次向导、真实 DPAPI 恢复及包审核。平台为托管 Windows Server 2022 x64。首次尝试在原有集成的“最后窗口关闭后重新打开”步骤发生连接超时，未进入新增原型测试；重跑通过不证明该偶发时序问题已修复，P3.4 继续复核进程退出与资料锁释放。

本检查点只交付底层启动能力和可执行原型。App 设置、切换操作的并发门禁和用户入口属于 P3.2/P3.3；自动重连和 App 重启恢复属于 P3.4。真实学校验证、真实课堂、macOS 系统钥匙串与实体设备仍待独立验收。

页面通过网站或现有加密会话恢复；**未提交的表单草稿、网页中的临时 DOM 状态不保证保留**。切回后台须在人工处理完成后进行，并再次核实网站答案回执，不能把重新加载视作提交成功。

## 生命周期规则

| 动作 | 目标行为 | 实现检查点 |
| --- | --- | --- |
| 关闭 App 主界面 | 托盘继续运行当前课堂，保持原截止时间 | P3.2 |
| 切换模式 | 串行保存、关浏览器、重启、复核页面；保留处理记录和原截止时间 | P3.2/P3.3 |
| 关闭有窗口课堂 | 明确暂停并提供恢复入口，不偷偷抢回焦点 | P3.3/P3.4 |
| 专用后台浏览器崩溃 | 显示重连，限定重试；无法恢复时提供人工入口 | P3.4 |
| 重启 App | 展示中断记录；恢复时保留原截止时间和去重记录，并核实当前页面 | P3.4 |
| 结束课堂 | 清理检查、提醒与定位，截止后不允许继续自动动作 | P3.2/P3.4 |
| 退出 App | 结束监控并清理专用浏览器，避免后台残留 | P3.4 |

上述规则为后续检查点的验收约定；P3.1 原型没有提前把 App 设置和恢复入口标为完成。

# 定时开启规则

P4.1 已实现共享规则、时间换算与执行决策，并在“连接与提醒”说明运行条件。配置界面与持久化属于 P4.2，实际自动调度属于 P4.3，时间变化与恢复属于 P4.4；本检查点尚不会自动开始课堂。

## 用户如何设置

选择已保存的课程、开始时刻（24 小时制）、城市时区和监控时长（1–720 分钟）。单次任务需要一个日期；每周任务选择星期几、开始日期及可选结束日期，两端日期都包含在内。日期范围为 2000–2100 年。时长表示实际经过的分钟数，跨午夜或夏令时也使用原定开始时刻加时长计算结束时刻。

时区默认使用创建任务时的电脑城市时区，并明确显示在预览里；保存后固定使用该时区，旅行或电脑时区改变不会自动改时。不要使用 `CST` 等容易混淆的缩写。暂停后不执行；新建、修改或重新启用时记录生效时刻，只允许原定开始时刻不早于该时刻的实例执行，避免保存操作意外补开刚刚错过的课堂。

## 到点时的规则

| 场景 | 执行规则 | 用户提示 / 处理入口 |
| --- | --- | --- |
| 尚未到点 / 已暂停 | 等待，不领取执行 | 尚未到开始时间 / 任务已暂停 |
| 关闭 App 主窗口 | 托盘里的 App 继续运行 | 可从菜单栏或系统托盘查看状态 |
| 退出 App、关机或睡眠 | 期间无法执行，不主动唤醒电脑 | 提前打开 App，保持电脑清醒 |
| App 重开或唤醒，迟到 ≤10 分钟，尚未到原结束时间 | 补开剩余时间；包括恰好迟到 10 分钟 | 已补开本次剩余时间，结束时间保持原计划 |
| 迟到 >10 分钟，或已到原结束时间 | 本次跳过，不开始完整的新时长 | 已错过本次开始时间；下一次计划仍保留 |
| 保存 / 重新启用时，本次开始时间已过 | 不追溯执行，未来实例继续保留 | 开始时间早于任务生效时间，已跳过 |
| 手动课堂或另一任务正在运行 | 保留当前课堂，本次跳过 | 已有课堂正在运行，本次任务已跳过 |
| 上次课堂等待恢复，或当前课堂登录过期 / 断网 / 窗口关闭 | 同样算冲突；不替用户结束或恢复旧课堂 | 先处理当前课堂，下一次计划仍保留 |
| 两个计划同时到点 | 按原定开始时刻、任务 ID 固定排序；先开始的占用课堂 | 后一个记录冲突并跳过，不排队补开 |
| 课程被删除 / 环境不可用 | 本次跳过，明确原因 | 重新配置课程 / 到设置页检查环境 |
| 登录过期、学校验证或人工题 | 启动后复用课堂状态和提醒 | 用户点击入口处理；自动检查保持前台焦点 |
| 开始时刻在夏令时跳过的区间内 | 单次配置拒绝保存；每周仅跳过该实例 | 开始时刻不存在，请选择其他时刻 |
| 开始时刻因夏令时出现两次 | 使用较早的一次，每个当地日期只执行一次 | 预览标出“重复时刻，采用第一次” |

例如计划 09:00–10:00：09:08 唤醒可监控到 10:00；09:11 唤醒会跳过。计划仅持续 5 分钟时，09:05 已经结束，即使仍在 10 分钟迟到范围内也不补开。

第一版**不提供开机启动选项**。它依赖已运行的托盘 App；用户主动退出后不会由系统再拉起。后续可独立验证 macOS 登录项与 Windows 安装版 / ZIP 的路径、启动时机和关闭选项，再提供默认关闭的选项。此决策不会阻止当前单次和每周任务开发。

## 开发约定

实现位于 `src/shared/schedule.ts`。`validateSchedule` 检查完整配置和课程引用，`occurrenceOnDate` / `occurrencesBetween` 将当地日期转换为执行实例，`decideSchedule` 给出等待、跳过或开始及面向用户的原因，`compareOccurrences` 确定冲突顺序。函数为纯规则，不启动浏览器、操作真实课堂或写系统设置。

- 使用明确的城市时区和 `Intl.DateTimeFormat.formatToParts` 做双向核对；发现时区变化前后的 UTC 偏移后，逐一验证候选时刻。不存在的当地时刻保留为明确的无效实例，不静默挪到下一小时；重复时刻取较早值。
- 实例键为“任务 ID + 当地日期”。同日时间 / 时区编辑及夏令时回拨不会产生第二个键。执行服务需在副作用前持久化领取记录；同键已领取后不重试开始。保存、取消和触发前再次核实当前配置，拒绝旧预览，具体持久化和竞态验证在 P4.3 / P4.4 完成。
- 已运行课堂的截止时间独立于后续计划编辑。任务重新启用只影响未来实例；页面回执、既有答案保护和课堂去重继续由 Watchdog 负责。
- 所有时间比较使用注入的 `now`，计划结束时间使用原定开始时刻计算。系统时间变化后的记录和幂等边界在 P4.4 验证。
- 日志后续记录实际开始、迟到、跳过及失败，不把“已到计划时间”视为签到或答案回执。原始个人配置、课程名和测试截图仍保留在本机。

`Intl` 的城市时区数据来源及标识规则参见 [ECMA-402 时区规范](https://tc39.es/ecma402/#sec-use-of-the-iana-time-zone-database)。当地时间存在跳过 / 重复的情况参见 [TC39 时间与时区歧义说明](https://tc39.es/proposal-temporal/docs/zoneddatetime.html#ambiguity)；本产品明确选择拒绝 / 跳过及第一次执行的策略，并未依赖运行环境支持 Temporal。时区法定规则可能变化，当前换算使用运行环境附带的时区数据，预览和执行须使用同一规则版本。

# 日历互动设想：`@tt`（Phase 5）

这是设计提案和合成事件演练，**当前 App 尚未连接 Google Calendar 或 Apple Calendar**。P5.1 定义使用语义；P5.2 核实官方接入条件；P5.3 定义到 Phase 4 的映射；P5.4 制作隔离样例并决定后续实现范围。完成本阶段不代表真实授权、同步或课堂接入已交付。

## 最小使用路径

设计中的用户先在 App 保存课程并完成登录，然后在已授权来源中选择需要识别的日历。[P5.2 官方接入调研](calendar-provider-research.md) 记录授权、撤销及平台限制；这里的流程仍是设计，不能当作现有操作指南。选择日历是 App 的读取过滤，不会缩小 Google OAuth 或 Apple 系统实际授予的权限。

1. 创建有明确开始、结束和时区的课堂事件，例如 10 月 5 日 09:00–09:50，America/Chicago。
2. 标题填写 `@tt 示例课程 A`。这里的课程名与 App 已保存名称一致；时长直接取事件开始到结束的实际分钟数。
3. App 的识别预览显示课程、日期、固定时区、预计结束及运行条件。第一次发现事件时，由用户确认绑定与启用；后续同一事件的合法修改可更新尚未开始的计划。
4. 信息不足时显示需要补齐的字段，并保留草稿。课程不匹配或同名时，用户从已保存课程中选择；没有确认的绑定不会自动开始。
5. 到点后复用 Phase 4 的托盘调度、最多 10 分钟补开、原截止、冲突和去重规则。预览“已生成计划”和运行“已启动监控”都不等于签到成功；网站回执仍分别显示。
6. 取消事件或删除 `@tt` 会撤销尚未开始的关联计划。若课堂已经开始或已开始启动，保留本节监控和原结束时刻，提示到 App 的课堂面板手动结束。

用户只需要课程名称和日历日期 / 时间，不需要填写坐标、Chrome 参数、账号令牌或内部课程 ID。定位、答案模式和登录使用 App 的既有课程配置。

## `@tt` 是什么

第一版提案把 `@tt` 定为**事件标题或描述中的独立文本标记**，大小写不敏感；不是日历邀请对象或 agent 邮箱，也不依赖平台的自动提及功能。标记不会发送邀请、消息或修改参与者名单。官方资料确认 Google 事件的标题 / 描述和 Apple EventKit 的标题 / notes 可用于这种文本识别；实际读取仍受账号权限和授权限制，尚未接入验证，详见 [接入调研](calendar-provider-research.md)。

推荐写法只有两种：

```text
标题：@tt 示例课程 A
开始 / 结束：在日历日期与时间字段中设置
```

或者保留原来的事件标题，在描述中写：

```text
@tt
课程：示例课程 A
```

标记前后必须是文本边界、空白或分隔标点。`@TT`、括号中的 `(@tt)` 可识别；`@tt123`、`name@tt.example`、`@tt.example` 和 URL / 邮件地址内的片段不作为指令。重复写标记只表示同一个事件的一次意图。这里规定识别行为，尚未交付产品解析器。

标题采用“标记 + 完整课程名”或“完整课程名 + 标记”时，可以提议精确匹配；其他标题使用描述中的 `课程：` 行。允许等价的英文字段 `Course:`。名称只去除首尾空白，不做模糊匹配、子串匹配或自动选第一门课。标题和描述给出不同课程、多个课程字段、同名课程或已删除课程时，预览要求人工选择。既有明确绑定优先沿用原课程 ID；改成另一门课必须重新确认，课程重命名不偷偷换绑。

事件文字只提供识别所需的标记与课程名称。描述中的“运行命令”“修改定位”“自动登录”等文字不作为可执行指令；它们也不能覆盖本机课程配置。

## 最少信息与预览结果

| 信息 | 要求 | 不满足时的行为 |
| --- | --- | --- |
| 事件身份 | 来源能稳定区分日历及事件；修改和取消可关联既有绑定 | 等待来源核实，不创建重复计划 |
| `@tt` | 独立标记出现在标题或描述中 | 新事件忽略；已绑定事件撤销未来计划 |
| 课程 | 唯一已保存课程，且已由用户确认绑定 | 选择或重新配置课程 |
| 开始 / 结束 | 明确的定时事件；实际时长 1–720 分钟 | 补齐时间，不默认为 50 分钟 |
| 时区 | 可确定原事件的城市时区或可核对的时间信息 | 补齐时区，不猜电脑当前时区 |
| 有效状态 | 事件未取消，且同步信息完整 | 取消未来计划或等待再次读取 |

全天事件不作为课堂计划。跨午夜可以识别，但时长仍受 720 分钟上限约束。无法唯一换算的时间、尚未核实的重复规则 / 例外、部分读取或读取失败都保留为待处理，不能当作删除或成功同步。重复事件和修改 / 删除的技术映射在 P5.3 展开。

预览采用五种清楚结果：**待确认、需要补齐、课程需选择、已取消未来计划、保留当前课堂**。未标记的新事件不出现在课堂识别列表。首次确认后才能成为可执行计划；之后如果需要改变绑定课程或遇到歧义，暂停未来同步计划并重新请求确认。

## 修改、取消与已开始课堂

| 用户动作或来源变化 | 尚未开始的关联计划 | 已开始 / 正在启动的实例 |
| --- | --- | --- |
| 修改合法开始 / 结束时间 | 更新预览和原计划，不另建一份；补开仍受生效时刻规则限制 | 不重新开启、不延长；显示原截止，人工决定本次是否延长 |
| 改成另一门课程 | 暂停计划并重新确认绑定 | 保留当前课堂，不切换课程 |
| 移除标记或明确取消事件 | 取消关联的未来实例 | 保留当前课堂，提供手动结束入口 |
| 暂时读不到日历 / 网络错误 | 显示同步未确认并暂停相关未来计划；既有绑定及记录保留 | 本节按原课堂状态和截止处理 |
| 同一事件再次被读取 | 更新识别时间；内容未变时不重存任务或改变生效时刻 | 不重复开始、签到或作答 |

首次确认、修改后启用和恢复同步时都遵守 Phase 4 的新生效时刻规则：不会因为导入刚刚过去的事件而突然补开。对已启用计划的 App 重启或电脑唤醒才应用最多 10 分钟补开。事件移到另一日期也不能使已执行的同一事件实例再次运行；稳定实例身份在 P5.3 定义。在 App 内暂停或取消关联计划也应保持用户的选择，下一次读取事件不会自行恢复；重新启用需用户明确操作。

## 合成事件演练

[calendar-intents.json](examples/calendar-intents.json) 使用自定义、平台无关的说明格式，包含合成课程与 16 个场景。它不是 Google / Apple API 响应，也不含真实账号或课程。`expected` 表示本设计的预览行为，尚未通过真实日历解析器执行。

| 场景 | 预期结果 |
| --- | --- |
| `@tt 示例课程 A`，时间完整 | 提议唯一课程，等待首次确认 |
| 普通标题，描述有标记和课程行 | 同样等待确认，保留原事件标题 |
| 大小写或重复标记 | 一次意图，不生成多份 |
| 同名课程 / 未保存课程 / 标题描述冲突 | 课程需选择，不自动绑定 |
| 无结束、无时区、全天事件 | 需要补齐，不默认开始或时长 |
| 未标记 / 邮件地址中的片段 | 忽略新事件 |
| 已绑定事件取消或移除标记 | 取消未来计划，保留历史事实 |
| 已开始事件改时或取消 | 保留当前课堂、原截止和答案记录，人工处理本次 |

## 隐私和范围

设计只读取用户在 App 中选择的日历、识别其中标记事件；读取后才能判定标记，所以未标记文本也可能短暂经过读取过程，不应持久化为诊断。预览只需要最少身份、标题 / 课程字段、时间、时区和取消状态。Google 可申请只读 scope，但不会按 App 选择限制到单个日历；Apple EventKit 的读取必须申请 full access，系统不提供只读授权，App 需自行限制为读取。账号授权与撤销条件见 [接入调研](calendar-provider-research.md)，实际保存字段待 P5.3 定义。原始私人日历不进入公开示例、日志附件或 GitHub；诊断只保留必要的错误分类，不记录授权令牌。

本阶段没有真实连接、后台日历同步、写日历、发邀请、创建课堂或实际调度导入。P5.1 的完成标准是语义与 16 个合成场景一致；P5.2 形成官方接入条件及建议路线，映射和隔离样例留给后续检查点。
